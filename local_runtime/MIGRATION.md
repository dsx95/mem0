# 换机器：整库迁移与恢复

迁移包括全部用户、家庭、成员、设备关系、内置和长期记忆、向量、修改历史、完整对话、日记、隐藏/删除标记、
上传任务、事实版本/冲突候选/未完成索引任务、原始资料和解析附件。保留记忆 ID 和时间，搬运已有向量时不调用 embedding 或 LLM，不需要重复上传资料。
旧版 `knowin_public` 对话也保留，恢复为“公共资料（旧版只读）”身份；普通私人用户仍按各自权限读取。

这是**整个本机实例**的迁移，不是将两个正在使用的记忆库自动合并，也不是普通用户下载其他成员私人数据的入口。

## 网页操作

1. 旧机器打开首页右上角「系统迁移」。在该机器的项目终端执行 `bash migrate.sh token`，将管理码填入弹窗。
2. 等待对话回复和资料导入结束，点击「生成完整迁移包」，再点击「下载迁移包」。链接十分钟有效，仅当前所选用户可下载；本机也保留导出文件。
3. 在新机器获取同版或更新版代码，执行 `bash start.sh --doctor` 安装环境，再用原来的模型配置启动服务。
4. 新机器打开「系统迁移」，使用**新机器自己的**管理码，上传 `.tar.gz`。先查看记录数量及模型/维度校验结果。
5. 点击「准备恢复，重启后生效」。这一步开始暂停新的写入，仍可读旧数据；也可点击「取消待恢复任务」。
6. 在启动服务的终端按 Ctrl+C 停服，然后使用原来的启动命令重启，例如 `bash start.sh --port 18582`。
   启动器先备份并恢复，然后才打开数据库。完成后刷新网页，重新选择用户。

整库管理码保存在 `.migration-key`，权限 600，不随迁移包导出，也不保存在网页 localStorage 中。
网页身份 Cookie 不迁移，恢复后旧 Cookie 失效。正常登录/切换用户仍按当前无密码模式运行。
这不是密码登录或多租户权限的替代方案；API 和 CLI 运维入口都只用于受信任的本机环境。

## 命令行操作

先安装环境，然后停止记忆服务。导出与恢复都会检测运行锁，拒绝操作正在使用的数据库：

```bash
bash start.sh --doctor
# 停止服务后，在旧机器导出；默认不含 API Key。
bash migrate.sh export
# 如确实需要将 Key 一起带走，可显式选择：
bash migrate.sh export --include-secrets

# 新机器先校验；此操作不修改当前数据库。
bash migrate.sh inspect /path/to/memory-xxxx.tar.gz
# 恢复并自动备份当前数据。
bash migrate.sh restore /path/to/memory-xxxx.tar.gz
bash start.sh --port 18582
```

全局选项放在子命令前：`bash migrate.sh --profile openai restore 文件.tar.gz`。
可用 `--root /path/to/project` 指向另一份已停止的 `data/ materials/ config/` 目录进行导出或恢复。
旧的 Docker/Coder 目录也可使用：先停止源服务、复制这三份目录到本机暂存目录，再 `--root 暂存目录 export`。
不能直接把旧的 Docker 镜像 tar、整个代码压缩包或任意数据 tar 上传当成本格式迁移包。

如果新机器已登记用户、家庭或设备，并希望保留这些关系：

```bash
bash migrate.sh restore /path/to/memory-xxxx.tar.gz --keep-local-identities
```

该选项只合并 `app_users / app_families / app_members / app_devices`，不合并两边的对话和向量。
家庭/设备 ID 已存在但属性或归属不同会拒绝恢复。目标用户名称冲突时以迁移包为准；原数据完整保留在恢复前备份中。
同一包重复恢复会替换数据，不会叠加生成重复记忆，但会再次生成目标数据备份。
如果待恢复包出错导致启动停止，可执行 `bash migrate.sh cancel` 取消待恢复任务，再正常启动原数据。

## 文件、校验与恢复保障

迁移文件默认位于 `migrations/`，自动备份位于 `migrations/backups/<时间-随机ID>/`，不进入 Git。
备份包含当时完整的 `data/ materials/ config/`。恢复出错时会回滚目录切换；进程中途退出后，下次启动先处理恢复日志，
再打开数据库。不要删除待恢复期间的上传包、暂存目录或 `restore-journal.json`。

迁移包包含版本清单、每个文件的 SHA-256、记录数量和模型标识。导入校验包结构、哈希、SQLite 完整性、集合和记录 ID。
禁止路径穿越、符号/硬链接、重复文件、触发器、虚拟表；不直接导入 Qdrant 的 pickle 文件，而是用 JSON 向量重建本地索引。
支持单个包最多 100000 个文件、解压后最多 50 GB；网页上传上限 20 GB，超过时使用命令行。
哈希用于校验内容完整性，不是来源签名；请只恢复自己保管的迁移包。

恢复前严格核对 embedding 平台、地址、模型、维度和集合，任一不符都拒绝。更换 embedding 模型应另做重新索引。
LLM 可随后调整。当前机器已有的 `.env` 配置和 Key 优先保留；新机器没有配置时恢复包中的配置，缺失 Key 由启动器提示填写。
默认清空配置中的 API Key/Token/Password/Secret 字段；只有显式勾选/加参数才携带。迁移包**未加密**，仍包含私人记忆和资料，
应通过受信任渠道传输并放在受保护的位置；机器切换后可轮换 Key。

包不包含 Python `.venv`、uv 缓存、运行锁、管理码、旧登录令牌、可重新下载的模型缓存、调试日志、旧备份或应用代码。
新机器重新执行 uv 安装，系统级 LibreOffice 仍需按格式需求另外安装。原始文件与解析附件都携带，路径自动映射到新目录。
备份、上传包和导出包不会自动清理；确认新机器完整可用后，维护者可按保留策略清理，避免磁盘持续增长。

## 迁移后核对

查看迁移结果中的数量，再核对用户下拉框、家庭/设备关系、记忆列表、完整对话、每日记事和一份附件下载。
旧库可能保留没有现存对话的历史测试用户绑定，这些绑定也会保留；因此新版用户列表可能比旧页面更长。
旧版没有日记的对话会在首次启动时回填原文；摘要按原来的自动整理配置处理，可能产生后续 LLM 调用。
只读公共资料账号的旧对话不生成私人日记。

## 事实版本的格式兼容

本版导出 v2 迁移包，新版可导入 v1 和 v2。v2 必须使用本版或更新代码恢复，旧代码拒绝 v2，
防止忽略新事实状态后把旧向量当作有效事实。导入结果区分向量数、长期事实数、版本数和未完成任务数；
冲突或撤回的事实可能没有向量，不能要求两者数量相等。恢复后继续处理未完成索引任务，可能调用 embedding。
旧版自由文本保留原 ID 和时间迁入事实表，不推断对象/属性或真实发生时间。升级前应备份数据；
不能把含新事实表的数据直接降级交给旧代码服务，回滚须同时恢复升级前备份。
