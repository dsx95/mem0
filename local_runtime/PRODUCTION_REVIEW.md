# 记忆模块产品化评估（2026-09-25）

范围：本仓库的 local_runtime 网页、聊天、资料导入、日记及可选重排序。结论来自代码检查和本地测试，
不是生产压测、渗透测试或真实模型质量认证。现阶段适合单所有者本机/受信任私有环境试用。

P0：面向多个真实用户或接入设备动作前完成。P1：小规模正式运营前完成。P2：按规模与测量结果推进。

| 优先级 | 项目 | 当前实现与实际缺口 | 可能的坑 | 建议和验收条件 |
|---|---|---|---|---|
| P0 | 登录与家庭成员授权 | chat.py 的 session/user/family 标识来自请求；dashboard.py 防跨站与 Host 检查只保护本机控制台，没有认证。总览可访问多个用户记录。 | 将过滤键或随机 session_id 当成权限；换 ID 读取别人的日记、附件或删除数据。 | 登录态绑定 user_id；服务端成员表校验 family_id；所有列表、详情、下载、修改接口做对象授权。跨用户/家庭负面测试必须拒绝，家庭退出后立即失权。 |
| P0 | 隐私、保留期限与删除 | 每轮原文进 chat.sqlite/日记；提示词限制不保存长期事实，不等于停止保存聊天；删会话保留 Mem0 长期记忆。 | 用户点“不记住/删除”仍在长期记忆、摘要、附件或备份中残留；私有内容发送至模型供应商。 | 区分无痕、保存聊天、提取长期记忆、家庭共享；统一删除任务覆盖衍生记录和附件，设保留期及备份过期规则；检索证明被删除内容不可见。 |
| P0 | 事实冲突与时态 | 聊天 remember 使用 infer=False；有创建/更新时间，没有完整 occurred_at、有效区间、supersedes 版本链。 | 新导入的旧日记被当成最新事实；临时行为误覆盖长期偏好；Rerank 高分被当成真相。 | 建立事实主表、事件时间和记录时间、有效/已替代/待确认状态；先判定是否同人同物同属性，查询当前状态过滤旧版。覆盖变化、历史补录、纠错、成员意见不同四类测试。 |
| P0（接设备） | 房间、物品、坐标的权威来源 | 目前通用文本/JSON 可入库；home_memory.db 的结构化事实方案仍是设计文档，尚无空间版本、单位、坐标系约束。 | 模型从旧文本猜坐标并触发错误动作。 | SQL/业务服务保存实体 ID、坐标系、地图版本、更新时间和置信来源；向量仅辅助找对象；动作前读权威状态并校验约束。 |
| P0 | 备份与恢复 | README 有停机拷贝流程；缺自动一致性备份、恢复演练和明确恢复目标。 | 运行中直接复制 SQLite/WAL/Qdrant 文件形成不一致备份；只备份向量遗漏源文件和元数据。 | 定义 RPO/RTO；协调写入后备份 SQL、Qdrant、资料、配置版本及加密密钥管理；用空机器恢复并验证计数、引用和检索。 |
| P1 | 跨库写入一致性 | 对话和日记同 SQLite 事务；Mem0/Qdrant 写入与对话日志不在同一事务。已有请求去重、导入 hash 和重试，但不是完整事务保证。 | 模型写入成功后进程崩溃，日记未关联；重试形成重复事实或孤儿索引。 | 业务事实事务加 outbox，稳定幂等键及版本 CAS；索引可重建；在各写入节点注入崩溃，重启后不重复不丢记录。 |
| P1 | 真实检索质量与回归 | 有范围隔离、混合检索、重排协议测试；模型主要使用替身验证，暂无中文家庭场景标注集。 | 英文 spaCy/BM25 对中文姓名、短句、别称效果不稳；更换模型/分片使准确率下降却没察觉。 | 建覆盖否定、时间、多人同名、冲突、无答案、PDF/OCR 的评测集，分别测 Recall@K、nDCG、回答正确率/引用匹配和 P95 延迟；Rerank 开关做 A/B。 |
| P1 | 路由与上下文预算 | grounding.py 有关键词路由及产品字段；chat.py 仍有产品特定扩展。某些明确记忆问句强制 search，未必走 diary；短期窗口为最近 12 轮/32000 字符。 | “昨天聊过什么”被只查向量；多语言不命中规则；长记忆在截断后丢失答案。 | 明确日记/当前事实/资料/闲聊路由及低置信回退；用模型 token 预算、结构化切片；多语言、跨天及长文本用例验证。 |
| P1 | 注入与错误事实传播 | 提示词把资料标为数据；引用检查能核对 ID、原文、数字/单位/网址，无法证明语义推导正确。普通回答并非全部强制核验。 | 恶意文档诱导错误写记忆；真实引文搭配错误结论；日记摘要错误再次进入长期事实。 | 服务器控制写入目标/类型，抽取结果带来源与置信状态；重要写入确认；维护注入与错误归因测试。证据检查与相关性模型不能替代权限控制。 |
| P1 | 并发与容量 | SQLite、本地 Qdrant、单进程锁、全库 snapshot、内存线程队列。Rerank 在数据库锁外；向量/模型部分仍在共享锁内。 | 增加 Web worker 争用同一路径；慢 embedding 阻塞其他用户；全库扫描随数据增加变慢。 | 先测负载和锁等待；多人服务使用 Qdrant Server，按并发写入需求迁 PostgreSQL；分页和索引替代全库扫描；限定任务并发、大小、速率。 |
| P1 | 日记任务与成本 | 每轮触发后台整理，合并短时间请求后重新处理当天全文；摘要版本校验已做，失败保留原文；启动只恢复最多 2 个 pending 日。 | 日内对话越多重复 token 越多；多用户积压、失败日一直没补齐；原始凭证仍可能进入模型输入。 | 分段增量摘要+日终合并；持久任务队列、租约、退避及死信；按用户预算/敏感信息规则；停机重启后所有到期任务可追踪恢复。 |
| P1 | 延迟、费用与可观测性 | 工具事件记录耗时，Rerank 返回 applied/fallback 和耗时；尚无统一指标、告警、租户配额、熔断。 | API 持续失败每轮都等待；Rerank 回退被当成启用成功；摘要与工具多轮请求费用累积。 | 记录各阶段 P50/P95/P99、token/费用、错误率和回退率；限额、熔断、超时总预算；不在日志记录 Key 和私人原文。 |
| P1 | 资料生命周期与解析安全 | 支持多格式、文件 hash 去重、受限路径与上传大小；缺统一文档修订/撤销策略、解析隔离和权限继承。 | 同文件新版本旧分片仍被召回；恶意/超大 PDF、视频耗尽资源；公开资料混入家庭私有数据。 | 文档版本与有效状态、源到分片反向索引；撤销同步索引/缓存；解析进程隔离、页数/时长/内存预算，资料继承业务权限。 |
| P2 | 发布、迁移与缓存 | 有锁定依赖、uv 启动和校验清单；缺明确数据库迁移版本、灰度/回滚流程。尚无 Redis。 | 直接改 schema 无法回滚；换 embedding 维度混库；缓存键遗漏家庭或权限版本导致泄露。 | 加版本化迁移及回滚演练，embedding/切片版本新建集合并切换；Redis 仅按需求用于缓存/限流/队列，缓存键含租户、用户、家庭与权限版本，更新删除同步失效。 |

## 建议实施顺序

1. 先确定部署场景。单家庭本机可继续 SQLite；开放给互不信任的多用户前先做登录/成员授权、删除隐私策略、备份恢复。
2. 再做事实主表/冲突版本与 outbox，避免后续规模化后补账；若接机器人，同时做结构化空间状态和动作约束。
3. 建真实评测集、性能/费用指标，再决定 Rerank 参数、增量日记、缓存、PostgreSQL 和 Qdrant Server 的投入。

Redis 不是产品化的前提，也不能替代事实数据库、权限校验或备份。SQLite 是持久数据库；何时迁移应由并发写入、
多实例部署和恢复要求决定。相关原理见 [SQLite 适用场景](https://www.sqlite.org/whentouse.html)。
本仓库使用 qdrant-client Local Mode，不是 Qdrant Server 或 Qdrant Edge；扩展部署方式参见
[Qdrant Client 官方说明](https://github.com/qdrant/qdrant-client)。

对象授权检查参见 [OWASP API1](https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization/)。
Rerank 协议与输入预算参见 [百炼官方接口](https://help.aliyun.com/zh/model-studio/text-rerank-api)。
