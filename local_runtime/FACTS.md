# 事实版本、冲突确认与索引同步

适用于本仓库的网页和聊天服务。事实正文及版本以 `data/dashboard/chat.sqlite` 为准，
Qdrant 是可异步更新的检索索引。部署仍是单进程 SQLite + Qdrant Local，不需要 Redis。
这个模块补齐事实生命周期；不代表无密码演示系统已经具备完整生产认证、分布式容量或全链路隐私清理。

## 如何管理

首页「长期记忆」默认包含当前有效、冲突待确认、已撤回的记录；可以单独筛选。
「详情与历史」展示全部版本、原始依据、提交人、发生/记录时间、有效截止时间与处理记录。
自己的内置资料、完整对话、每日记事仍在对应分页中；勾选「包含对我隐藏」可管理隐藏的记录。
日记展示原始对话和摘要偏好候选，摘要不会自动覆盖长期事实。

新增长期事实时填写「对象」「属性」「内容」。例如对象 `小林`，属性 `饮品偏好`，内容 `小林喜欢牛奶`。
一条记录对应一个对象的一个属性；集合偏好应使用一个完整集合值，或拆为更精确的属性，避免不同爱好被误判互斥。
后续在详情点「更新 / 纠错」，可以选择：

| 操作 | 例子 | 处理 |
|---|---|---|
| 事实发生变化 | 从今天起改喝豆奶 | 新版本有效；旧版本标记已被替代，记录有效截止时间 |
| 纠正错误 | 原记录写错，本来就不喝牛奶 | 新版本有效；原版本标记已撤回，不能当作过去的真实状态 |
| 提交冲突候选 | 不确定两种说法哪个对 | 记录进入待确认；双方说法保留，暂停作为当前事实召回 |
| 处理冲突 | 保留原记录或采用候选 | 创建者/家庭管理员确认并写原因，未选候选标记未采纳 |
| 撤回事实 | 该信息不再可靠 | 停止当前检索；保留版本历史供用户查看 |
| 删除 | 用户要求删除该记忆 | 删除正文、全部版本和候选，清理索引与历史副本；保留不含正文的删除标记防止任务复活 |

发生时间必须带时区，不能是未来；留空表示提交时刻，**不代表模型推断了实际发生时间**。
未来安排可写在内容中。迟到的旧观测不会按记录时间直接覆盖新状态，会进入确认流程。
用户明确选择「纠错」时才允许用较早的证据纠正原来的错误。

私人事实只有本人可以修改/删除；家庭共享事实只有记录创建者或家庭管理员可以处理版本及删除。
其他家庭成员可提出不同说法并触发待确认，或仅对自己隐藏。公共资料只允许普通用户隐藏，不能删掉公共原件。
device_id 标记来源，不能绕过 user_id 和 family_id 权限。

## 冲突识别的边界

同一记忆范围内，`规范化对象 + 规范化属性` 唯一标识事实槽位。相同正文重试不新增版本；
同槽位的新说法默认是候选，不会因为向量分数高或写入较晚就覆盖。不同对象的相同文本不会混为一条。
更新已知事实时使用稳定的 memory_id，并携带 revision；版本变化返回 409，必须刷新后重新决策。

聊天工具被要求先查找现有事实、复用对象/属性或事实 ID，关联当前用户原话；只能提交 assertion，
不能自行执行 change/correction。当前轮原话引用在服务端验证，不接受模型捏造的引文。
新的聊天事实必须有对象/属性；仍需评测模型是否正确拆分和归一化。
“本人/我/自己/user/me”等有限的一人称写法会绑定为当前登录身份 `user:<user_id>`，防止家庭成员相互混淆。
本版没有独立实体别名库或通用语义矛盾模型，**不能保证昵称、全名、物品别称等所有改写自动落到同一槽位**。
旧的自由文本按原 ID 迁入，保留创建/更新时间与旧修改历史，未猜测对象和真实发生时间；用户可在更新表单分类。
CLI/原生 Mem0 仍是受信任运维入口，直接调用它们不会执行本层冲突策略，不应作为产品写入口。

## 数据与事务

| chat.sqlite 表 | 内容 |
|---|---|
| facts | 事实 ID、范围、对象/属性、当前版本、状态与 revision |
| fact_versions | 各版本全文、状态、有效时间、记录时间、原话和原因 |
| fact_events | 修改动作、操作者、时间和 revision |
| fact_outbox | 待同步版本、状态、失败次数、下次重试时间 |

事实变更、事件和 outbox 在一个 SQLite 事务内提交。返回成功表示权威记录已落盘，
不意味着 embedding 和 Qdrant 已同步。网页实时显示同步状态；变更后的正文立即可在管理页查看。
聊天召回会用 SQL 当前正文替换旧索引内容，过滤冲突、撤回、删除和隐藏记录，
并为尚未同步的有效事实补充候选；补充仍受最终候选数量限制，不保证每条待同步事实都被召回。
网页语义搜索依赖向量，因此新记录同步完成前可先用列表/关键词查看。

## 后台任务：既有步骤依赖，也有任务排队

- 步骤依赖：例如解析文档 → 切片 → embedding → 写索引；后一步依赖前一步结果。
- 任务排队：多个用户/文件/记忆同时提交时，限制并发、防止内存和模型额度被耗尽。
- 恢复保障：即使只有一条任务，也需要处理超时、进程重启、重复提交和过期结果。

本版事实索引采用持久 outbox：每个事实最多一条待执行目标，同一事实连续更新会合并到最新 revision，
但版本历史仍完整保留。单进程只执行一个索引任务，embedding 不占用数据库锁。
模型返回后重新检查 revision，旧任务不能覆盖新版本或重建已删除事实。
失败按指数退避重试（最长等待 300 秒），累计 8 次进入失败状态，用户可在「记忆同步任务」中重试。
重启会恢复未完成任务。迁移准备恢复期间暂停索引提交。

这不是整个系统的统一任务调度器：资料导入、日记汇总仍使用原队列。
大规模下发还需要租户配额、队列上限、取消/优先级、跨任务公平调度、指标告警以及工作进程租约；
多进程部署需更换 Qdrant Server 并设计相应数据库/任务协调，不能直接增加本地 Web worker。

## API

沿用 [用户与设备接口](IDENTITY_AND_DEVICES.md) 的 Cookie、身份一致性 Header 和写请求 Header。

| 接口 | 参数/结果 |
|---|---|
| GET /api/manage/memories | memory_type=longterm；fact_status=all/active/disputed/retracted；可按家庭/设备和隐藏状态过滤 |
| GET /api/manage/records/{id} | 获授权记录完整详情，包括隐藏记录；普通召回仍排除隐藏记录 |
| GET /api/manage/facts/{id} | 正文、revision、versions、events、legacy_history、sync_status |
| POST /api/manage/notes | memory_type=longterm, text, subject, attribute, occurred_at, family_id, device_id, scope |
| PATCH /api/manage/facts/{id} | revision, text, kind=change/correction/assertion, occurred_at, reason；可选 subject/attribute |
| POST /api/manage/facts/{id}/resolve | revision, version, kind=change/correction, reason |
| POST /api/manage/facts/{id}/retract | revision |
| DELETE /api/memories/{id} | 按权限删除该记忆及全部版本；索引清理可能异步重试 |
| GET /api/manage/tasks | 当前用户可见的未完成事实索引任务 |
| POST /api/manage/facts/{id}/retry | 重新排队；仍需修改/删除该事实的权限 |

删除单条事实不会删原始对话、资料文件、解析缓存或已有备份。完整遗忘需分别删除相应原始记录并执行保留策略。
应用仍保留权限归属和无正文删除标记用于一致性恢复，不应把单条删除宣传为全系统无痕擦除。

## 升级与迁移

升级前停服备份。启动自动创建四张表并迁入已有长期记忆，不重新计算旧向量。
事实版本与未完成 outbox 从 v2 起包含在迁移包中；当前含待办回收站的导出格式为 v4，新版读取 v1/v2/v3/v4。
须用支持对应格式的代码恢复，旧版不认识新数据状态，不能降级后直接服务新数据库。
需要回滚时，停服并恢复升级前数据备份；详见 [迁移说明](MIGRATION.md)。
