# 待办清单：网页、聊天与接口

首页左侧「待办清单」提供创建、查询、编辑、完成、重新打开、取消和删除。
在同一用户权限内，用「所属清单」组织购物、旅行准备、工作事项等不同清单；清单名是条目的分类，暂不支持空清单对象。
这是结构化待办管理，不是向量检索。没有 Top-K 截断；列表提供总数和分页。

## 表单字段

| 字段 | 规则 |
|---|---|
| 标题 | 必填，最多 240 字符 |
| 所属清单 | 默认“默认清单”，可填写购物清单、旅行准备等，最多 80 字符 |
| 详细说明与备注 | 最多 6000 字符，可写数量、目标、完成条件 |
| 状态 | 待确认 draft、待办 pending、进行中 in_progress、受阻 blocked、已完成 done、已取消 cancelled |
| 优先级 | 低 low、普通 normal、高 high、紧急 urgent |
| 创建时间 / 更新时间 | 后端自动记录；客户端不能伪造或修改 |
| 计划开始时间 | 可不填；填写后不能晚于截止时间 |
| 截止日期 / 截止时间 | 可不填；仅某天和精确时刻二选一 |
| 时区 | 默认 Asia/Shanghai，可指定 IANA 时区；精确时间按 UTC 保存 |
| 完成时间 / 取消时间 | 改成对应状态时自动记录；重新打开时清空当前完成/取消时间，旧操作保留在历史中 |
| 发起人 `initiator_user_id` | 即原来的创建者 `owner_user_id`，由登录身份自动确定，不能由客户端或 LLM 冒充；响应中两个名称指向同一人 |
| 家庭 / 可见范围 / 来源设备 | 创建时选择并做服务端验证，之后固定，防止编辑时意外改变共享范围 |
| 执行人 `assignee_user_id` | 一位主要负责人；私人任务默认自己，共享任务可留空或指定同一家庭现有成员 |
| 协作成员 `participant_user_ids` | 需要谁协作，可多选、去重，最多 30 人；只允许同一家庭现有成员，私人事项只能选择本人；返回 participants 提供 ID 和显示名 |
| 所需资源 `required_resources` | 最多 2000 字符；所需物品、资料、预算或外部联系人说明，不授予任何权限 |
| 完成标准 `completion_criteria` | 最多 2000 字符；明确怎样才算完成 |
| 受阻原因 `blocked_reason` | 最多 2000 字符；等待事项、困难或阻碍，修改它不会自动切换状态 |
| 完成说明 `completion_note` | 最多 2000 字符；交付结果及遗留事项，不自动标记完成 |
| 实际耗时 `actual_minutes` | 可不填，0–525600 分钟，由人填写，不自动计时 |
| 实际开始 `actual_started_at` | 首次进入 in_progress 时后端自动记录，重新打开仍保留；旧数据不编造历史开始时间 |
| 完成操作人 `completed_by` | 进入 done 时自动记录操作用户；重新打开清空，历史保留原操作者；不一定等于执行人 |
| 提醒计划开关 `reminder_enabled` | 默认 false；仅保存计划，尚未接入投递 |
| 提醒时间 `reminder_at` | 带时区的精确时刻，UTC 保存；启用时必填 |
| 提醒失效时间 `reminder_expires_at` | 带时区的精确时刻，必须晚于提醒时间；启用时必填，独立于任务截止时间 |
| 提醒内容 `reminder_note` | 可选，最多 500 字符 |
| 地点 | 最多 240 字符 |
| 标签 | 最多 10 个，每个最多 40 字符，去掉空标签和重复标签 |
| 预计耗时 | 可不填；1–10080 分钟 |
| 子任务 | 最多 50 项，每项有稳定 ID、内容及完成勾选；不会自动完成整条待办 |
| 来源 | 网页/接口或聊天；聊天创建保存来源会话、轮次与用户原话，只有创建者能查看这些私人来源信息 |
| 操作历史 | 每次修改的操作者、时间、版本及字段变化 |

只说“某天截止”时按该时区当天结束计算，不猜测具体几点。逾期由当前时间推导，只有已确认且未完成的事项可能逾期；
不因逾期自动完成或取消。网页“今天/未来 7 天”按北京时间筛选，API 可用 timezone 改变筛选时区。
日期跨夏令时按指定时区处理；网页遇到不存在或重复的本地时刻会要求调整或使用 UTC 明确填写。

## 权限和删除

- 私人待办仅本人可读写；同一设备不会让其他用户看到私人事项。
- 共享待办仅当前家庭成员可读。创建者或家庭管理员可修改完整内容和删除。
- 指定执行人可修改状态、子任务、受阻原因、完成说明及实际耗时；不能擅自改标题、截止日期、指派、协作人员或提醒计划。协作名单只描述参与关系，不额外授予编辑权限。
- 无负责人权限的其他成员只能查看；退出家庭后共享记录立即不可见。
- 当前沿用本机无密码身份选择，这不是正式认证；上线前仍需真实登录。
- 完成/取消保留记录和历史；删除先移入回收站，保留原状态、子任务、来源和历史，正常列表与聊天预读不再返回。回收站暂不自动清空。
- 创建者或当前家庭管理员可以恢复；彻底删除须在回收站输入完整标题并携带当前 revision，清除正文、来源、操作历史与删除确认。仅保留创建请求哈希及 ID，防止重试复活。
- 原始对话及其中的工具记录、日记、已有备份独立管理，不因删除待办自动擦除；本版没有待执行提醒任务。
- 单条删除不是全链路遗忘。公开 CLI/原生 SDK 也不能代替这个带身份授权的 HTTP 层。

## 聊天和语音接入

聊天增加 `todo` 工具，操作为 list / get / members / create / update / delete。对话中的 user_id、family_id、device_id 来自绑定会话；
新建的私人/共享范围取本轮 remember_scope，不能由模型在 data 中注入身份或共享范围。
members 只返回当前家庭的成员 ID 与显示名；个人空间只返回本人。模型先查询真实 ID，再指定执行人/协作成员，同名或身份不明时询问用户。
写入要求 source_quote 是当前用户输入中的真实连续原文。更新/删除使用真实 task_id 与 revision；
同名候选有多条时提示模型先澄清；创建/更新返回 changed 后才可声称成功。

delete 仅返回 requires_confirmation=true 和确认卡，不能执行删除。用户必须点击网页卡片确认；模型没有确认、恢复或彻底删除工具。
确认绑定用户、待办 ID、revision、来源会话和轮次，有效期 10 分钟。任务修改、退出家庭、原对话删除、取消确认或超时会阻止执行；跨用户不能确认。
确认消费后重试不会再次删除，已恢复任务也不会被旧确认重新移入回收站。刷新页面会重新读取确认状态。
外部 Agent 应显示同样的确认 UI，由用户明确点击后调用确认 API；不可让模型自行请求该接口。纯语音回复“确认”目前不执行删除。

例如：“帮我创建待办，下周五前买两盒牛奶，放到购物清单。”“把买牛奶改到下周六。”“牛奶买好了，标记完成。”
工具提示词要求解析相对日期、区分待确认计划与确定事项；这部分仍依赖实际 LLM 的理解，需要真实场景评测。
“我的待办清单”一类明确请求直接预读 SQL 清单；向量/embedding 不可用不会阻止这条待办查询路径。
模糊说法可能仍走普通聊天路由，由模型选工具；不能保证任意自然语言都触发操作。

语音系统将 ASR 文字发送到现有聊天接口后可使用同一工具。本次没有新增麦克风采集或 ASR 服务。
待办查询默认包含当前家庭范围内本人的私人和家庭共享事项，不跨当前会话的家庭操作。
分页返回 total / has_more / page；模型不能把第一页称为全部。
为控制上下文成本，工具列表裁剪长描述并仅返回子任务进度；详情返回子任务，完整内容和操作历史始终在网页/API 中保留。

本版**可持久化提醒计划，但不主动发送提醒，不支持周期自动生成任务或自动执行事项**。
提醒时间和提醒失效时间须成对填写或清空，关闭开关时可保留原时间，方便后续启用。启用时两者必填，不能自动猜测用户未说明的失效时间。
截止时间决定任务是否逾期，失效时间只决定提醒计划的时间窗口，两者相互独立。计划可以在截止后失效，不会自动取消或完成任务。
reminder_state 为只读推导值：disabled（关闭）、inactive（待确认/已完成/已取消/回收站）、scheduled（尚未到时间）、due（已到提醒时间但未失效）、expired（达到失效时刻）。
这些状态不表示实际发送结果；reminder_delivery 恒为 not_configured，网页及聊天会明确提示未接入响铃或推送。重新打开/恢复任务时按原计划与当前时间重新推导。
未来接入调度器后仍需增加通知渠道、接收人、投递记录、幂等重试与撤销机制，不能仅凭 reminder_enabled 判断已经设置有效闹钟。

## API

沿用 [身份接口](IDENTITY_AND_DEVICES.md) 的 Cookie、X-Memory-Client 和 X-Memory-User。

| 接口 | 内容 |
|---|---|
| GET /api/todos | 按权限查询；默认所有状态，page=1、page_size=20（最多 100） |
| POST /api/todos | 新建，title 必填；推荐携带唯一 request_id，重复请求返回原记录 |
| GET /api/todos/{id} | 完整字段、权限标志和全部操作历史 |
| PATCH /api/todos/{id} | `{ "revision": 1, "changes": { "status": "done" } }` |
| DELETE /api/todos/{id}?revision=2 | 按版本移入回收站，返回 trashed=true |
| POST /api/todos/{id}/restore | `{ "revision": 3 }`，恢复原状态 |
| POST /api/todos/{id}/purge | `{ "revision": 3, "title": "完整标题" }`，彻底删除 |
| GET /api/todo-delete-confirmations/{id} | 当前确认状态 pending / stale / expired / confirmed |
| POST /api/todo-delete-confirmations/{id}/confirm | 用户明确点击后执行，仍校验权限和版本 |
| DELETE /api/todo-delete-confirmations/{id} | 取消待执行确认 |

列表默认只查当前待办；trashed=true 专查回收站。详情 GET 可以查看有权限的回收站记录。
列表支持 family_id、device_id、status、period、priority、assignee_user_id、list_name、q、timezone、page、page_size。
status=open 包括待确认、待办、进行中、受阻；period=all/today/upcoming/overdue/unscheduled。
upcoming 表示从查询时区明天开始的 7 个自然日。q 对标题和详细说明做文字包含查询，list_name 精确匹配。
家庭/设备参数空表示所有可见范围，`__none__` 表示未设置；负责人 `__none__` 表示暂未指派。

创建示例：

```json
{
  "request_id": "client-generated-unique-id",
  "title": "准备周末旅行用品",
  "list_name": "旅行准备",
  "description": "带上证件和充电器，出发前确认车票。",
  "status": "pending",
  "priority": "high",
  "due_date": "2030-06-15",
  "timezone": "Asia/Shanghai",
  "visibility": "personal",
  "estimated_minutes": 30,
  "required_resources": "身份证、充电器和车票",
  "completion_criteria": "核对清单后全部装箱",
  "participant_user_ids": [],
  "reminder_enabled": true,
  "reminder_at": "2030-06-15T09:00:00+08:00",
  "reminder_expires_at": "2030-06-15T10:00:00+08:00",
  "reminder_note": "出发前再检查证件",
  "tags": ["旅行"],
  "checklist": [{"text": "确认车票", "done": false}]
}
```

精确时刻用 due_at（带时区的 ISO 字符串）。改截止方式时同时清空另一字段，例如
`{"due_date":"","due_at":"2030-06-16T15:00:00+08:00"}`。创建/完成时间不能通过请求体覆盖。
修改发生并发冲突返回 409，应重新读取后决策；相同创建请求删除后重放返回 410，不复活数据。
request_id 由浏览器生成，聊天由轮次和操作内容生成；API 不携带 request_id 时不能保证创建重试不重复。

## 持久化和迁移

继续使用 `data/dashboard/chat.sqlite`，包含 todos、todo_events、todo_requests；另有短期删除确认表 todo_delete_confirmations 和成员退出审计表 app_membership_events。
旧 todos 表自动增加 deleted_at / deleted_by、actual_started_at / completed_by。新增业务字段（协作成员、资源、完成标准、执行结果、提醒配置）保存在 todos.data JSON 中。
首次启动会给旧 JSON 补空值、空列表和关闭开关，不改变已有字段、ID、revision 和历史时间；不编造旧任务的实际开始时间或完成操作人。发起人沿用 owner_user_id，不重复维护身份列。
正文、状态和历史在同一 SQL 事务内提交；更新携带 revision，避免旧请求覆盖新状态。
不新增数据库服务，不调用 embedding，不将待办写成长期事实；原始聊天照常进入已有对话/日记流程。

整库迁移导出版本为 v5，包含完整待办字段、回收站、操作历史、幂等标记和成员退出审计；新版可读取 v1/v2/v3/v4/v5。
导出/恢复会清除副本中的登录令牌和删除确认，原机器确认不受导出影响；迁移后需重新发起删除。
旧版无法导入 v5 包，避免忽略新增字段或误处理回收站数据；新机器需使用本版或更新代码。升级前备份，回滚须同时恢复旧库。

## 成员退出

在“家庭与设备”中可主动退出；家庭管理员可移除其他成员。管理员本人退出须指定现有成员接任，最后一位成员暂不能退出，不自动解散家庭。
共享待办保留在家庭中；原指派或协作成员包含离开成员的任务（含回收站）原子地解除指派/移除协作关系，同一条只递增一次版本并记入历史，私人待办不被删除或改归属。
旧删除确认失效，重新加入也不恢复旧指派、协作关系或确认。已存在的历史孤立指派在不改指派人的任务更新时自动清空。
家庭仍有活跃聊天时返回 409，完成或停止后再退出。退出后旧家庭会话不能继续发送，需切换个人或其他家庭。
共享资料和家庭设备不随成员离开删除；历史对话、日记和备份不会被远程擦除。
